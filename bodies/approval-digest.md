Before: a request-less approval card (from older gateways, and the card a push restores) was updated in place when Hermes announced the next command, and a tap answered whatever the card held by the time AppState got to it. The Always allow confirmation stays up while the card can change, and it answered the card as it was when confirmed, not as it was when tapped. The command was cut at five lines on both the chat and group cards, so Run could approve lines nobody could see. Bidi overrides (U+202E), zero-width, tag and control characters and stacked combining marks in the command or its explanation drew as nothing or reordered the text around them.

After: the card hands over the approval as it drew it, and AppState sends nothing if the card now asks something else (another request id, command, explanation, set of offered choices, `allowPermanent` or `smartDenied`). The command is shown in full up to about twelve lines and scrolls inside that height past them, and any hidden character shows as `<U+XXXX>` instead of being dropped, because the command runs as sent.

How: `ApprovalActivity.asksSameAs(_:)` compares what the person reads; status, error and the session id don't count, so a retry after an error and the move to the durable id still go through. `respondToApproval(messageId:choice:shown:)` takes the shown approval (default nil, so the voice-call path is unchanged) and returns early on a mismatch; the card already shows the new question. The Always allow confirmation uses `confirmationDialog(presenting:)`, so it answers the approval it was opened for. `ApprovalDisplayText.revealingHidden(_:)` escapes Cc (except tab, LF and the CR of a CRLF), Cf, Co, Cn, Zl and Zp, plus combining marks past three on one base; a ZWJ between two pictographs is kept, and ordinary text comes back unchanged. `ApprovalCommandBox` is a small `Layout`: a hidden, accessibility-hidden copy of the command is measured at the offered width, the box takes `min(that, 12 lines)`, and the visible `ScrollView` is laid out in exactly that box (bounce only when it scrolls, indicator flashed on appear). The height is settled in the first layout pass, with no state and no measure-then-shrink, so the lazy chat list never sees the row at full length. The cost is one hidden copy of the command text per card. No new strings.

His "truncated means no inline Allow" rule became "never truncate the command".
