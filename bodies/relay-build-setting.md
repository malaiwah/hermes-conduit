Before: push registration (`POST /v1/installations`) and the token challenge always sent `bundle_id: "com.milim.relay"`, whatever bundle ID the app was built under. A build signed under another bundle ID for a self-hosted relay registered as upstream's app, so the relay pushed to the wrong APNs topic. Its users also had to type the relay URL into Settings > Notifications > Push relay, because the default was hard-coded to `https://push.milim.dev`, and the field's placeholder kept showing that URL.

After: the relay is told the running app's own bundle ID; for upstream's build that is still `com.milim.relay`, so nothing changes there. A build can set `CONDUIT_DEFAULT_RELAY_URL` (for example `xcodebuild CONDUIT_DEFAULT_RELAY_URL=https://push.example.com …`) to make its relay the default, and the Settings placeholder shows that default. The setting is empty in project.yml, so upstream builds still default to `https://push.milim.dev`.

How: `registrationBundleID(Bundle.main.bundleIdentifier)` falls back to `com.milim.relay` when the identifier is nil or empty. `PushNotificationService` is compiled only into the app target, so an extension's bundle ID can never be the one sent. `project.yml` adds `CONDUIT_DEFAULT_RELAY_URL: ""` and Info.plist carries it as `ConduitDefaultRelayURL`. `buildDefaultRelayURL(info:)` trims the value, runs it through the existing `usableRelayURL` check and requires `https`; anything else (empty, unexpanded `$(…)`, no host, `http`, a non-string) falls back to `https://push.milim.dev`. The placeholder was a literal URL with no catalog entry, so no strings change. The README's "Running your own relay" gets one sentence.

Review notes: in an `.xcconfig`, `//` starts a comment, so `CONDUIT_DEFAULT_RELAY_URL = https://x` is cut to `https:`; that has no host and falls back to upstream safely (tested). In an xcconfig it has to be written `https:/$()/push.example.com`; the command line and project.yml are unaffected. `defaultRelayURL` is still a `nonisolated static let` read once and used as before; changing a build's default moves existing installations on the next relay change, the same as editing Settings.
